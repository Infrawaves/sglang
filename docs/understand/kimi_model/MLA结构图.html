MLA结构图：Kimi-K3.1 的 Gated Sparse-MLA + DSA indexer

K3.1 一共 24 个 MLA 层（KimiK3MLAAttention，python/sglang/srt/models/kimi_k3.py:2745），每一层都带 DSA 稀疏 indexer。下图画的是一层的结构，按推理时的权重吸收（absorbed）形态绘制。图中的 H、q_lora_rank、qk_nope、v_head_dim、n_idx、d_idx 等维度，仓库里没有真实 config，所以用符号表示。

各组件说明

组件形状作用TP8TP8 + PCP8TP8 + DCP8
latent KV 投影（fused_qkv_a_proj_with_mqa 中的 c_kv、k_pe，以及 kv_a_layernorm）7168 → 512 + 64把每个 token 压缩成所有头共享的 576 维 latent，写进 KV cache权重复制，每卡对全部 token 计算权重复制，每卡只算 1/8 token，再 all-gather权重复制，每卡对全部 token 计算，只有 owner 卡写入
Q 投影（c_q → q_a_layernorm → q_b_proj，以及吸收时的 W_UK）7168 → q_lora_rank → H × (qk_nope + qk_rope)低秩分解的 query。q_nope 乘 W_UK 吸收到 latent 空间，和 latent KV 直接点积q_b_proj 按头切成 8 份权重完整复制，1/8 token × 全部头开 --dcp-replicate-q-proj 时复制。decode 时每卡在本地算出全部头的 Q；prefill 时按头切分
indexer K（wk → LayerNorm → FP8）7168 → d_idx每个 token 一个不带 RoPE 的轻量 key，写进 Index K cache复制计算每卡算 1/8 token，再 all-gather每卡都算，只有 owner 卡写入。prefill 时 gather 整个序列，decode 时只在本地打分
indexer Q 和头权重（wq_b、weights_proj）c_q → n_idx × d_idx；7168 → n_idx对历史 token 打分：score = Σ_h w_h·ReLU(q_idx_h·k)，选 top-k复制。K3.1 行数多时把 query 行拆给各 TP rank（_indexer_tp_split）每卡只对本卡的 1/8 query 打分decode：本地 top-k → all-gather 候选 → 合并成全局 top-k（dcp_global_topk）
稀疏 attentionq̃ [T,H,576] 对 top-k 个 latent只在选中的 token 上做 softmax attention，输出 latent 空间的 o_lat全部 token × 1/8 头1/8 token × 全部头，本地有完整 KV，不需要 LSE 合并prefill：gather 完整 KV 后按头切分计算；decode：只算本卡选中的 KV，再用 fi_a2a / push-combine 按 LSE 合并
V 解压（W_UV）512 → v_head_dim（每头）把 latent 输出映射回每个头的 V 空间按头切分复制按头切分；decode 时可以先做 V 预投影再交换（dcp_v_preproject）

o_projH × v_head_dim → 7168输出投影，结果加到残差上行并行，做 all-reduce复制，不需要归约行并行，做 all-reduce
说明
  • 图中按权重吸收的形态绘制：q_nope 乘 W_UK 吸收进 latent 空间，attention 直接在 576 维 latent 上做，输出再乘 W_UV。W_UK 和 W_UV 是 kv_b_proj 拆出来的两部分（代码里是 w_kc / w_vc，deepseek_v2.py:2294-2305）。
  • K3 的 MLA 构造时传入 skip_rope=True（kimi_k3.py:2788），k_pe 和 q_pe 这 64 维仍然存在，但不做旋转。位置信息来自 KDA 层。
  • indexer 的打分公式按 DeepSeek DSA 的标准形式写，用来说明原理。K3.1 的 indexer 不用 RoPE（index_rope_dim == 0），K 用 LayerNorm，头权重用 BF16（configs/kimi_linear.py 的 _init_dsa）。
  • 656 B 和 132 B 是根据 cookbook 给出的 18.9 KB/token（24 层合计）拆算的。H、q_lora_rank、qk_nope、v_head_dim、n_idx、d_idx、index_topk 的具体数值，仓库里没有真实 config，所以没有核实。
  • Kimi-K3（非 .1）的 MLA 层没有 indexer，图中绿色的部分都不存在，attention 是 dense 的。
