3. 各类结构的层数

每一层由一个注意力子层加一个 FFN 子层组成。两种子层各自有两种类型，按层号选择：

子层类型层数怎么判断属于哪种
注意力KDA（KimiK3DeltaAttention）69config.is_kda_layer(i)：(i+1) in linear_attn_config["kda_layers"]
Gated Sparse-MLA + DSA（KimiK3MLAAttention）24其余层，即 full_attn_layers。K3.1 要求 dsa_layers == full_attn_layers，也就是每个 MLA 层都带 DSA indexer（kimi_linear.py:157-162）
FFNdense MLP（KimiK3MLP）1layer_idx < first_k_dense_replace。推断是第 0 层：Maas 的权重统计里写的是 "layer0 MLP"
Latent MoE（KimiK3MoE）92_is_moe_layer：i ≥ first_k_dense_replace 且 i % moe_layer_freq == 0（kimi_k3.py:3014）
层间连接Attention-Residual bank最多 8 个快照attn_res_block_size：layer_idx % block_size == 0 的层写入一个快照（kimi_k3.py:3237）
KDA 层和 MLA 层是怎么排列的： 69:24 接近 3:1。Kimi Linear 系列通常是"3 层 KDA 后接 1 层 MLA"交错排列，但 93 不是 4 的倍数，实际顺序要看 checkpoint config 里的 linear_attn_config.kda_layers 和 full_attn_layers（1-based 层号）。代码只依赖这两个列表，不假设任何固定规律。
Attention-Residual 的块大小： bank 的快照数是 ceil(93 / attn_res_block_size)（kimi_k3.py:3537），代码注释写的是 "K3 has <= 8 snapshots"（attn_residual.py）。要让 ceil(93/B) ≤ 8，块大小 B 至少是 12。所以推断 B=12：第 0、12、24、…、84 层各写一个快照，共 8 个。具体值以 config 为准。

4. 解码层内部结构

KimiK3DecoderLayer(layer_idx = i)
├── self_attn  = KimiK3DeltaAttention     if is_kda_layer(i)       # 69 层
│               KimiK3MLAAttention        otherwise                # 24 层（K3.1 都带 DSA）
├── mlp        = KimiK3MoE                if _is_moe_layer(i)      # 92 层
│               KimiK3MLP (dense)         otherwise                # 1 层
├── input_layernorm           RMSNorm(7168)   # 注意力输入的输出 norm
├── post_attention_layernorm  RMSNorm(7168)   # FFN 输入的输出 norm
└── (Attention Residuals)
    ├── self_attention_res_norm  RMSNorm(7168)    ┐ 注意力子层读 bank 时
    ├── self_attention_res_proj  Linear(7168 → 1) ┘ 给每个快照打分
    ├── mlp_res_norm             RMSNorm(7168)    ┐ FFN 子层读 bank 时
    └── mlp_res_proj             Linear(7168 → 1) ┘ 给每个快照打分

层内的计算顺序（KimiK3DecoderLayer.forward，kimi_k3.py:3355-3399）：

x_attn_in = input_layernorm( Aggregate_attn(bank, running_residual) )   # attn_boundary.prepare
a         = self_attn(x_attn_in)                                         # KDA 或 MLA
running_residual += a                                                    # attn_boundary.finish（PLAIN_ADD）
x_ffn_in  = post_attention_layernorm( Aggregate_ffn(bank, running_residual) )   # ffn_boundary.prepare
f         = mlp(x_ffn_in)                                                # MoE 或 dense
running_residual += f                                                    # ffn_boundary.finish

和普通 pre-norm Transformer 的区别在于：送进子层的输入不是"上一层的残差"，而是"bank 中所有历史快照加上当前块的累加值"按 softmax 加权混合的结果。详见第 8 节。

5. KDA：Kimi Delta Attention（69 层）

KDA 是一种线性注意力，用带门控的 delta rule 维护一个固定大小的递归状态。它的推理成本不随上下文长度增长。

参数值来源
头数 num_heads96（Q/K/V 头数相同）Maas params.js："12 heads/rank at attn TP8"
头维度 head_dim128Maas params.js
投影宽度96 × 128 = 12288projection_size = head_dim × num_heads
短卷积核 short_conv_kernel_size4Maas params.js

子模块（KimiK3DeltaAttention.__init__，kimi_k3.py:2037-）

模块形状作用
q/k/v 投影（qkv_proj，或融合成 fused_qkvbfg_a_proj）7168 → 3 × 12288得到每个头的 q、k、v
qkv_conv1d沿时间维的 depthwise 卷积，核大小 4对 q/k/v 做局部混合，提供位置和局部信息。推理时要缓存最近 3 个 token 的卷积状态
b_proj7168 → 96每个头的写入强度 β（delta rule 的学习率）
f_a_proj → f_b_proj7168 → 128 → 12288（低秩）逐通道的遗忘门 α，配合 A_log、dt_bias 决定每个通道的衰减
g_a_proj → g_b_proj（或全秩门 use_full_rank_gate）7168 → … → 12288输出门
A_log、dt_bias参数衰减参数化
o_normFusedRMSNormGated(128, activation="sigmoid")每个头的输出做 RMSNorm，再乘 sigmoid(输出门)
o_proj12288 → 7168（RowParallel）输出投影
attn = RadixLinearAttention—执行卷积和递归的 kernel 封装，管理 KDA 状态缓存

计算过程（概念）

q, k, v = conv1d(qkv_proj(x))                # 短卷积，带因果
β       = sigmoid(b_proj(x))                 # 每个头一个标量
α       = decay(f_b(f_a(x)), A_log, dt_bias) # 每个头、每个通道一个衰减
# 每个头的状态 S ∈ R^{128×128}：
S_t = (I − β_t k_t k_tᵀ) · Diag(α_t) · S_{t−1} + β_t k_t v_tᵀ    # gated delta rule
o_t = S_tᵀ q_t
y   = o_proj( RMSNormGated(o, gate = g_b(g_a(x))) )

上面的递归公式是 KDA（Kimi Linear 论文）的标准写法，用来说明各个门的作用。sglang 中的实际 kernel 在 RadixLinearAttention 及其后端里。

和推理相关的特点： KDA 不需要随长度增长的 KV cache，每个请求只需要一份固定大小的状态（每个头 128×128 的 S，加上卷积状态）。状态默认是 FP32，cookbook 给的数字是 TP8 时约 52 MB / 请求 / rank。prefill 时需要按顺序处理完整序列，这就是 PCP 下 KDA 层必须先 gather 完整序列的原因。

6. Gated Sparse-MLA + DSA indexer（24 层）

KimiK3MLAAttention 继承自 DeepSeek-V2 的 DeepseekV2AttentionMLA，在它的基础上有三处改动：

① 不用 RoPE（NoPE）

构造时传入 skip_rope=True（kimi_k3.py:2788），MLA 层不做旋转位置编码。位置信息来自 KDA 层的递归和短卷积。这是 Kimi Linear 系列的设计。

② 输出门（Gated）

mla_use_output_gate：g_proj = ColumnParallelLinear(7168 → num_heads × v_head_dim)。在 o_proj 之前计算 x · sigmoid(g_proj(hidden))（kimi_k3.py:2866-2906）。

③ DSA 稀疏 indexer（K3.1 新增）

每个 MLA 层都有自己的 indexer（index_topk_freq == 1）。indexer 用 index_n_heads 个头、index_head_dim 维的 NoPE key（index_rope_dim == 0，K 用 LayerNorm），对历史 token 打分，选出 index_topk 个。attention 只在这些 token 上计算。

④ MLA 低秩 KV

kv_lora_rank = 512，qk_rope_head_dim = 64，每个 token 缓存 576 维 latent（Maas params.js）。用 FP8 FlashMLA 格式存储时约 656 B/token/层，加上 indexer K 约 132 B/token/层。
c_q   = q_a_proj(x) → RMSNorm → q_b_proj           # q_lora_rank 低秩
c_kv  = kv_a_proj_with_mqa(x)  → [latent 512 | k_rope 64]   # 写入 KV cache（FP8）
idx_k = indexer_k(x) → LayerNorm                   # 写入 indexer K cache
topk  = TopK( indexer_q(x) · idx_k_history ,  index_topk )  # DSA 选择
o     = SparseMLA(q, c_kv[topk])                   # 只在选中的 token 上做 MLA
y     = o_proj( o * sigmoid(g_proj(x)) )

cookbook：24 个 DSA 层合计约 18.9 KB/token（24 × (656 + 132) B）。index_topk、index_n_heads、index_head_dim 的具体值需要看 config 的 dsa_config，仓库里没有。

7. FFN：Latent MoE（92 层）与 dense MLP（1 层）

7.1 Latent MoE（KimiK3MoE，kimi_k3.py:565-）

路由专家不在 7168 维的 hidden 空间里计算，而是先投影到一个更小的 latent 空间（routed_expert_hidden_size），在那里计算，再投影回 7168 维。共享专家仍然在原始 hidden 空间计算。

x (7168)
├── router: MoEGate(x) → sigmoid 打分 + e_score_correction_bias
│           → grouped top-k（DeepSeek-V3 风格，noaux_tc）→ 选 16 / 896 个专家
├── 路由分支（Latent）:
│     z = routed_expert_down_proj(x)            # ReplicatedLinear: 7168 → latent
│     z = Σ_{e∈top16} w_e · Expert_e(z)        # 每个专家: SiTU-GLU，在 latent 空间里
│     z = routed_expert_norm(z)                 # 可选（latent_moe_use_norm）
│     r = routed_expert_up_proj(z)              # ReplicatedLinear: latent → 7168
│     r = r × routed_scaling_factor
├── 共享分支: s = SharedMLP(x)                  # 2 个共享专家合成一个 MLP，
│                                               # intermediate = moe_intermediate_size × 2
└── 输出 = r + s

这样设计的好处：专家的输入维度变小，dispatch/combine 的通信量和专家 GEMM 的计算量都随之下降。代码里会把 router、down 投影和共享专家的 gate_up 合并成一次 "fused front" GEMM（_front_w）。

7.2 dense MLP（KimiK3MLP，第 0 层）

y = down_proj( SiTU(gate) ⊙ up ),   [gate, up] = gate_up_proj(x)

7.3 SiTU 激活（layers/activation.py 的 SituAndMul）

gate' = β · tanh(gate / β) · sigmoid(gate)        # β = 4.0
up'   = β_lin · tanh(up / β_lin)                  # β_lin = 25.0，对 up 做软裁剪
out   = gate' ⊙ up'

和 SiLU 相比，SiTU 对 gate 和 up 都做了有界的软裁剪，数值更稳定，适合 MXFP4/MXFP8 的量化训练。MegaMoE kernel 把 β=4.0、β_lin=25.0 写死了，加载 checkpoint 时会断言这两个值。

8. 层与层怎么连接：Attention Residuals

这是 K3 系列最特别的地方。普通 Transformer 的残差是 h_{l+1} = h_l + F(h_l)，每一层只能看到前面所有输出的直接累加。K3 改成了"按块保存快照，再加权读取"。

8.1 机制（layers/attn_residual.py 的 AttnResidual，layer_boundary/residual/attn_bank.py）

  • bank：每次前向开一个形状为 [T, NB, 7168] 的快照缓冲区，NB ≤ 8。
  • running residual（块内累加值）：当前块里各子层输出的累加和。
  • 写快照：layer_idx % block_size == 0 的层，在注意力的读取点把当前累加值存进 bank 的下一行，然后块内累加值清零重新开始。第 0 层存的是 embedding 本身（attn_residual.py："Layer 0 attention side: nothing banked yet"）。
  • 读（聚合）：每个子层的输入都这样计算： 
    rows   = [bank[0], bank[1], …, bank[nvb−1], running_residual]     # nvb+1 行
score  = res_proj( res_norm(rows) )          # 每行一个标量，res_proj: 7168 → 1
p      = softmax(score)                      # 在这 nvb+1 行之间归一化，每个 token 独立
mixed  = Σ p_r · rows_r
input  = out_norm(mixed)                     # input_layernorm 或 post_attention_layernorm
    参考实现见 aggregate_stream_torch（attn_residual.py:324）。注意力子层用 self_attention_res_*，FFN 子层用 mlp_res_*。
  • 更新：子层的输出直接加到 running residual 上（PLAIN_ADD）。
  • 输出：最后一层之后，AttnBankOutputRead 用 output_attn_res_proj/norm 再聚合一次，然后过最终 RMSNorm，送进 lm_head。

8.2 以 block_size = 12 为例（推断值）

embedding ─► [快照0] ─────────────────────────────────────────────────────┐
layer 0..11   每个子层: 输入 = Norm(Σ softmax·{快照0, 累加值})              │
              输出累加到 running residual                                    │ 后面的层
layer 12      注意力读取点: 把 running residual 存为 [快照1]，然后清零        │ 都能按
layer 12..23  每个子层: 输入 = Norm(Σ softmax·{快照0, 快照1, 累加值})        │ 学到的权重
…                                                                            │ 直接读取
layer 84      存为 [快照7]                                                    │ 早期的
layer 84..92  输入 = Norm(Σ softmax·{快照0..7, 累加值})                      │ 表示
最终输出     Norm(Σ softmax·{快照0..7, 累加值}) → lm_head ◄──────────────────┘

作用： 深层可以按学到的权重直接取用浅层的表示，包括 embedding 本身，不必让信息穿过几十次累加。93 层这样的深网络因此更容易训练和保持数值稳定。代价是每个子层多一次 softmax 聚合（有专门的 TMA / Triton kernel），而且 PP 切分时要把 bank 一起传给下一个 stage（pp_proxy_tensors["attn_res_bank"]，kimi_k3.py:3540-3544）。

9. 多模态输入：MoonViT3d 与 projector

组件说明
KimiK3VisionTower（MoonViT3d）cookbook 写的是 MoonViT-V2，401M 参数。支持图像和视频（视频不含音轨）。KimiK3VisionConfig 的默认值是 patch 14、27 层、hidden 1024、12 个头，位置编码类型 divided_fixed，视频注意力类型 spatial_temporal，merge 核 2×2，merge_type="sd2_tpool"（空间 2×2 合并加时间池化）。这些是 config 类的默认值，实际以 checkpoint 为准。
KimiK3MultiModalProjectormm_projector_type="patchmergerv2"，把视觉特征投影到文本的 hidden 维度（7168）
和文本合并视觉特征替换 embedding 序列中 media_placeholder_token_id = 163605 的位置，之后和文本 token 一起进入 93 个解码层
部署相关ViT 以数据并行方式运行（use_data_parallel = True）。本分支对 ViT 预处理做了按块流式处理和 CUDA Graph 优化（multimodal/kimi_k3_vit_cuda_graph_runner.py，以及 vit[1–5] 系列提交）

10. 一个 token 的完整前向路径

token_id ──► embed_tokens ──► h0 (7168)          （图像 token 换成 ViT → projector 的输出）
           bank.open(); 第 0 层把 h0 存为快照0

for i in 0..92:
    # ---- 注意力子层 ----
    x  = input_layernorm( AttnResAggregate(bank, R) )      # 第 i%B==0 层先把 R 存入 bank 再清零
    if i+1 in kda_layers:   a = KDA(x)                      # 69 层：读写固定大小的递归状态
    else:                   a = GatedSparseMLA_DSA(x)       # 24 层：读写 latent KV + indexer K
    R += a
    # ---- FFN 子层 ----
    x  = post_attention_layernorm( AttnResAggregate(bank, R) )
    if i == 0:              f = DenseMLP_SiTU(x)            # 1 层
    else:                   f = LatentMoE(x)                # 92 层：top-16/896 + 2 个共享专家
    R += f

y = final_norm( OutputAttnResAggregate(bank, R) )
logits = lm_head(y)

11. 结构对推理缓存的影响

结构需要缓存什么大小并行方式对它的影响
24 层 Sparse-MLAlatent KV（576 维，FP8）+ indexer K约 18.9 KB/token，随长度线性增长TP 和 PCP 都是复制，只有 DCP 能按 token 切分
69 层 KDA递归状态 S（96 头 × 128×128）+ 短卷积状态每个请求固定大小（FP32，TP8 时约 52 MB/rank），乘以每个请求的状态槽数可以按头在 TP 内切分，DCP/DP/EP 都不切分它。cookbook："The KDA state pool is the concurrency ceiling"
Attention-Residual bank只在单次前向中存在，不跨请求缓存[T, ≤8, 7168] 的激活PP 时要随 hidden 一起传给下一个 stage

所以 K3.1 的显存分成两个池：分页的 MLA KV 池和预先预留的 KDA 状态池，两者的比例由 --mamba-full-memory-ratio 控制。prefix cache、HiCache 和 PD 传输都要同时处理这两类数据。

12. K3 与 K3.1 的区别

Kimi-K3（KimiK3ForConditionalGeneration）Kimi-K3.1（KimiK31ForConditionalGeneration）
MLA 层dense MLA，没有 indexer（"K3 has no indexer"，kimi_k3.py:2748）每个 MLA 层都有 DSA indexer，做稀疏 attention（KimiK31Config 文档："Kimi-K3 with DSA sparse attention on every MLA layer"）
其余结构相同：93 层，69 KDA + 24 MLA，Latent MoE 896/16+2，Attention Residuals，MoonViT
prefill CP不支持支持，走 CP-TP group sharing，策略是 interleave
后训练K3.1 Pro 从 K3 出发，做了大规模联合强化学习（cookbook）

代码层面，KimiK31ForConditionalGeneration 是 KimiK3ForConditionalGeneration 的子类（kimi_k3.py:4717），只是通过 config 打开了 DSA。投机解码的草稿模型（DFLASH 的 Kimi-K3.1-Dflash2-Preview，或 DSPARK）是独立的小模型，不属于主干结构。num_nextn_predict_layers 的默认值是 0。

未核实或推断的内容

  • attn_res_block_size = 12 是根据"最多 8 个快照"和 93 层推出来的。
