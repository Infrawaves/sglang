二、python/sglang/ 包结构

  • srt/（SGLang Runtime）：推理服务运行时，见第三部分。
  • lang/：SGLang 前端 DSL，包括 api.py、ir.py、interpreter.py、tracer.py，用来写结构化的 LLM 程序（gen、select、fork 等）。
  • kernels/：自研 kernel 的注册和选择层，包括 jit、aot、ops、arch、registry.py、selector.py，按硬件选用实现。
  • multimodal_gen/：扩散模型运行时，处理图像、视频、3D 生成，和 LLM 的 srt 是两套独立的东西。
  • cli/：命令行入口，sglang serve、generate、killall 等。
  • launch_server.py：启动服务的入口。
  • api/、benchmark/、test/、profiler.py、check_env.py：API 定义、压测工具、测试工具、性能分析、环境检查。

三、srt/ 运行时：请求流转路径与各模块

SGLang 用多进程架构，进程之间通过 ZMQ 通信：

HTTP/gRPC 请求
  → entrypoints（http_server / OpenAI 兼容 API）
  → TokenizerManager（分词、多模态预处理）        [主进程]
  → DataParallelController（DP>1 时分发请求）
  → Scheduler（调度、组 batch、管理 KV 缓存）       [每个 GPU rank 一个进程]
      → TpModelWorker → ModelRunner → 模型 forward → Sampler
  → DetokenizerManager（增量反分词）               [独立进程]
  → 流式返回给客户端

1. 入口层：entrypoints/

  • http_server.py：FastAPI 服务。
  • engine.py：离线 Engine API，可以不起 HTTP 服务直接调用。
  • openai/、anthropic/、ollama/：各家 API 协议的兼容层（Chat、Completions、Responses、Embeddings）。
  • grpc_server.py、grpc_bridge.py：gRPC 服务。
  • warmup.py：服务启动后的预热。

2. 请求管理与调度：managers/

  • tokenizer_manager.py：接收请求、分词、跟踪请求状态、汇总输出。
  • scheduler.py：核心事件循环。负责接收请求、组 prefill/decode batch、调用 worker、处理结果。具体功能拆在 scheduler_components/ 里：request_receiver、batch_result_processor、output_streamer、metrics_reporter、weight_updater 等。
  • schedule_policy.py：调度策略，比如按最长前缀匹配（LPM）优先、FCFS。
  • schedule_batch.py：Req 和 ScheduleBatch 这两个数据结构。
  • tp_worker.py：张量并行 worker，封装 ModelRunner。
  • detokenizer_manager.py：反分词。
  • data_parallel_controller.py：数据并行时分发请求。
  • io_struct.py：进程间传递的消息结构。
  • overlap_utils.py：CPU 调度和 GPU 计算重叠执行。

3. 模型执行：model_executor/

  • model_runner.py：加载模型、初始化 KV 池和 attention 后端、执行 forward。拆分出的部分在 model_runner_components/ 里。
  • forward_batch_info.py、forward_mode.py：ForwardBatch 结构和 EXTEND/DECODE/IDLE 等执行模式。
  • runner/：CUDA Graph 捕获和回放（decode、prefill、按行分桶），以及 eager 模式执行。

4. 模型与网络层

  • models/：约 260 个模型实现（Llama、Qwen、DeepSeek、Kimi K3 等）。
  • layers/：
    • attention/：可插拔的 attention 后端，有 FlashInfer、FlashAttention、Triton、TRT-LLM MHA/MLA、FlashMLA、AITer（ROCm）、DSA 稀疏注意力、线性注意力和 Mamba 等，通过 attention_registry.py 选择。
    • moe/：MoE 的 topk 路由、fused_moe_triton、cutlass/flashinfer MoE、EP 的 token dispatcher（DeepEP 等）。
    • quantization/：FP8、FP4、INT4、AWQ、GPTQ、ModelOpt 等量化方式。
    • linear.py、vocab_parallel_embedding.py、layernorm.py、rotary_embedding/：基础层，大部分支持张量并行。
    • communication/、dp_attention.py、cp/、dcp/：通信融合、DP attention、上下文并行。
    • logits_processor.py、sampler.py：计算 logits 和采样。
    • radix_attention.py：模型调用 attention 的统一接口。
  • model_loader/：权重加载，支持 safetensors、GGUF、expert pack 等格式。
  • configs/：各模型的 HF 配置适配。

5. 显存与 KV 缓存：mem_cache/

  • radix_cache.py：RadixAttention 前缀缓存（基数树），让请求复用相同前缀的 KV。这是 SGLang 的核心特性。
  • memory_pool.py、allocator/：token 到 KV 的映射表和分页分配器。
  • swa_memory_pool.py、hybrid_cache/、mamba_*：滑动窗口注意力、混合架构、Mamba 状态池。
  • hicache_*、memory_pool_host.py、storage/：HiCache 分层缓存，把 KV 卸载到 CPU 内存或外部存储（3FS、Mooncake 等）。
  • evict_policy.py：缓存淘汰策略。

6. 采样与约束解码

  • sampling/：采样参数、penalty、自定义 logit processor。
  • constrained/：结构化输出（JSON schema、正则、EBNF），后端用 xgrammar、outlines 等。
  • function_call/：各模型的工具调用解析器（如 kimik3_detector.py）。
  • parser/：推理内容（reasoning）解析。

7. 高级特性

  • speculative/：投机解码，包括 EAGLE/EAGLE3、多层 EAGLE、NGram、DFlash、Standalone 草稿模型等 worker 和对应的 CUDA Graph runner。
  • disaggregation/：Prefill/Decode 分离部署。prefill.py、decode.py 是两种角色，mooncake/、nixl/、mori/、ascend/ 是 KV 传输后端。
  • distributed/：parallel_state.py 管理 TP/PP/EP 通信组，device_communicators/ 是自定义 AllReduce、PyNCCL 等。
  • eplb/、elastic_ep/：专家并行的负载均衡和弹性扩缩。
  • lora/：多 LoRA 服务。
  • multimodal/：VLM 图像和视频预处理（processors/）以及视觉编码器。
  • batch_overlap/：Two-Batch Overlap，用两个 micro-batch 让计算和通信重叠。
  • weight_sync/、checkpoint_engine/、ray/：给 RL 训练用的在线权重更新和 Ray 集成。
  • compilation/：torch.compile 集成。
  • hardware_backend/、platforms/：CUDA、ROCm、NPU、XPU、CPU 等平台适配。
  • observability/：Prometheus 指标和 tracing。

8. 配置

  • server_args.py：所有启动参数，arg_groups/ 按功能分组，model_overrides/ 放各模型的参数覆盖。
  • environ.py：SGLANG_* 环境变量的统一定义。
